# Architecture — CheckmaîtréX AI

Single Cloudflare Worker (`checkmaitrex-ai`) with internal modular services. No additional Workers.

## Module map

src/ index.js — Router: CORS, rate limit, auth gate, endpoint dispatch auth.js — Supabase introspection auth, roles, owner check, secure IDs orchestrator.js — Central orchestrator: classify → quota → history → context → route → execute → validate → track → persist assistants.js — Four assistant profiles + manager (D1-backed with defaults) modelRouter.js — Capability-aware routing, compatibility matrix, circuit breaker modelRegistry.js — D1-backed model registry (22 seeded models) promptManager.js — Builds trusted system prompts (assistant config + club data) contextManager.js — Assembles untrusted context (knowledge + memory + engine) into user message memory.js — D1 conversations + consent-gated memory (ownership-scoped); guest KV sessions knowledge.js — D1 knowledge base with draft→publish lifecycle; prompt-injection boundary chess.js — Stockfish delegation (external endpoint); honest unavailability usage.js — Quota enforcement + usage summaries (costs labeled as estimates) handlers.js — Preserved existing handlers (all original endpoints) providers/ gemini.js — Gemini adapter (API key in header, not URL — fixes S4) workersai.js — Workers AI adapter (text + vision + streaming) migrations/ 001_platform_foundation.sql — 14 additive tables tests/ orchestrator.test.js — 10 test categories (mocked)


## Request lifecycle (orchestrator)

1. **Authenticate** — Supabase introspection (router-level)
2. **Identify assistant** — from `body.assistant` (default: `checkmaitrex`)
3. **Check permissions** — role-based; guests allowed for chat
4. **Check quota** — daily per-user + per-assistant limits
5. **Retrieve history** — D1 (users) or KV (guests)
6. **Detect chess** — FEN regex → engine analysis if configured
7. **Build system prompt** — trusted (assistant config + club data)
8. **Build context** — untrusted (knowledge + memory + engine) → appended to user message, NOT system prompt
9. **Route models** — capability-aware; never downgrades vision→text
10. **Execute** — provider fallback with circuit breaker
11. **Validate** — non-empty response check
12. **Track usage** — D1 usage_records
13. **Persist** — conversation + messages (D1) or guest history (KV)
14. **Return** — consistent JSON with requestId, model, assistant, quota, engineAnalysis

## Security boundaries

- **Trusted vs untrusted data**: system prompt = trusted (assistant config); retrieved knowledge/memory/engine = untrusted (delimited, in user context). This is the prompt-injection defense.
- **Ownership scoping**: all conversation/memory queries are `user_id`-scoped. Cross-user access is impossible by design.
- **Admin protection**: all `/api/admin/*` require admin key, owner key, or owner role — verified server-side.
- **Engine honesty**: chess.js returns `available: false` when no engine is configured. Never fabricates evaluations.

## E. Security Findings

1. **Rate limiting is in-memory (`Map`).** It resets per isolate and is **not enforced globally**. A distributed attacker can bypass it. Must move to KV or Durable Objects for reliable limits.
2. **Single KV namespace holds ALL data** — posts, conversations, owner knowledge, analytics, persona, usage, cache. No isolation boundary; no per-user scoping visible at the storage layer. Conversation keys (`conv:`) need user-prefix verification.
3. **Owner auth is a shared secret (`OWNER_KEY`).** No Google OAuth, no 2FA, no session revocation, no role-based access. The prompt requires Google-account identity + RBAC.
4. **`gemini-3-flash-preview` as `DEFAULT_MODEL`** — this model ID is unverified. It is overridden by the `GEMINI_MODEL` secret, but if that secret is unset the Worker will call a possibly-invalid model. Should validate model IDs against the registry.
5. **CORS is correctly scoped** to two origins (good), but CORS ≠ auth — admin operations must have server-side auth (currently only `OWNER_KEY`).
6. **No secrets exposed** in this audit (values not retrieved). Secrets are stored as Cloudflare secrets (good practice).

## F. Compatibility / Architecture Problems

- **No `wrangler.toml` / no Git-based deploy** for the Worker → configuration is not version-controlled; redeploying requires the dashboard or manual wrangler setup.
- **D1 bound but unused** → either remove the binding or implement the intended schema. Carrying an empty DB is a latent migration risk.
- **Monolithic 108 KB single file** → hard to maintain, test, or modularize into the orchestrator pattern the blueprint requires.
- **Workers AI binding present but unverified usage** → if unused, remove; if used as fallback, document it.

---

## G. Recommended Final Architecture (high level)

1. **Keep the two Workers** (AI + sync). Do not add unnecessary Workers.
2. **Refactor the monolith** into a modular orchestrator: `orchestrator → assistant-manager → model-router → provider-adapters → registry`.
3. **Activate D1** for relational/durable data (users, sessions, conversations, usage, audit logs, knowledge versions) with versioned migrations. Keep KV for cache + posts + fast config.
4. **Move rate limiting + quotas** to Durable Objects or D1-backed counters (durable, not in-memory).
5. **Add Google OAuth** (Access or custom) + RBAC (owner/admin/moderator/user/guest).
6. **Model registry** as D1 table + KV cache; validate every model ID before use.
7. **Stockfish:** Workers cannot run Stockfish WASM reliably within CPU limits. Recommend an external engine service (e.g., a separate container/edge function calling a hosted Stockfish, or Lichess cloud eval as the verified path) — document the constraint.
8. **Voice/image:** use Gemini multimodal + Workers AI where the provider genuinely supports it; never claim capabilities the model lacks.

// PRIMARY method: Supabase Auth token INTROSPECTION.
//   The Worker calls Supabase's own /auth/v1/user endpoint with the user's
//   access token. Supabase validates the token server-side and returns the
//   user record. This does NOT assume the project's JWT signing algorithm or
//   secret — it delegates verification to Supabase itself.
//
// OPTIONAL fast path: local HS256 JWT verification, used ONLY if the Owner
//   explicitly sets SUPABASE_JWT_SECRET after confirming the project uses the
//   standard Supabase JWT secret (HS256). If that secret is absent or the
//   algorithm differs, introspection remains the source of truth.
//
// Required Worker secrets (set by Owner in dashboard — names only, never values):
//   SUPABASE_URL          — e.g. https://.supabase.co
//   SUPABASE_ANON_KEY     — the project "anon" / "public" API key (safe to use
//                           server-side for the /auth/v1/user introspection call)
// Optional (fast path only — do NOT set unless you confirmed HS256):
//   SUPABASE_JWT_SECRET   — project JWT secret (Supabase Dashboard →
//                           Project Settings → API → JWT Settings → JWT Secret)
//   ADMIN_API_KEY         — bearer token for machine/admin API access
//   OWNER_KEY             — (legacy) optional owner bearer
//
// Never trusts a user id or email supplied only in a request body.

function base64UrlDecode(str) {
  str = str.replace(/-/g, "+").replace(/_/g, "/");
  const pad = str.length % 4 ? "=".repeat(4 - (str.length % 4)) : "";
  const bin = atob(str + pad);
  const bytes = new Uint8Array(bin.length);
  for (let i = 0; i < bin.length; i++) bytes[i] = bin.charCodeAt(i);
  return bytes;
}

// --- Optional local HS256 verification (fast path) --------------------------
async function verifySupabaseJWT(token, secret) {
  if (!secret) return null;
  const parts = token.split(".");
  if (parts.length !== 3) return null;
  let header;
  try { header = JSON.parse(new TextDecoder().decode(base64UrlDecode(parts[0]))); }
  catch { return null; }
  if (header.alg !== "HS256") return null; // do not assume other algorithms
  let data;
  try { data = JSON.parse(new TextDecoder().decode(base64UrlDecode(parts[1]))); }
  catch { return null; }
  const key = await crypto.subtle.importKey(
    "raw", new TextEncoder().encode(secret),
    { name: "HMAC", hash: "SHA-256" }, false, ["verify"]
  );
  const valid = await crypto.subtle.verify("HMAC", key, base64UrlDecode(parts[2]),
    new TextEncoder().encode(parts[0] + "." + parts[1]));
  if (!valid) return null;
  if (data.exp && Date.now() >= data.exp * 1000) return null;
  return data;
}

// --- PRIMARY: introspection via Supabase Auth API ---------------------------
async function introspectSupabase(token, env) {
  if (!env.SUPABASE_URL || !env.SUPABASE_ANON_KEY) return null;
  try {
    const res = await fetch(`${env.SUPABASE_URL}/auth/v1/user`, {
      headers: {
        "Authorization": `Bearer ${token}`,
        "apikey": env.SUPABASE_ANON_KEY,
      },
    });
    if (!res.ok) return null;
    const user = await res.json();
    if (user && user.id) return user;
    return null;
  } catch {
    return null;
  }
}

const MAX_FEN_LENGTH = 100;
const MAX_PGN_LENGTH = 50000;
const DEFAULT_DEPTH = 15;
const MAX_DEPTH = 30;
const ENGINE_TIMEOUT_MS = 10000;

function validateFEN(fen) {
  if (typeof fen !== "string" || fen.length > MAX_FEN_LENGTH) return false;
  // Basic FEN structure check: 6 space-separated fields
  const parts = fen.trim().split(/\s+/);
  if (parts.length < 4 || parts.length > 6) return false;
  const board = parts[0];
  if (!/^[pnbrqkPNBRQK1-8/]+$/.test(board)) return false;
  return true;
}

function validatePGN(pgn) {
  if (typeof pgn !== "string" || pgn.length > MAX_PGN_LENGTH) return false;
  return true;
}

/**
 * Analyze a position via the configured Stockfish engine endpoint.
 * @returns {Promise<{available:boolean, evaluation?:object, error?:string}>}
 *   The `available` flag is the source of truth — if false, NO engine ran.
 */
async function analyzePosition(env, fen, opts = {}) {
  const depth = Math.min(opts.depth || DEFAULT_DEPTH, MAX_DEPTH);
  const multiPv = Math.min(opts.multiPv || 1, 5);

  if (!validateFEN(fen)) {
    return { available: false, error: "Invalid FEN" };
  }

  const engineUrl = env.CHESS_ENGINE_URL;
  if (!engineUrl) {
    // HONEST: no engine configured. Do not fabricate.
    return { available: false, error: "Chess engine not configured. Set CHESS_ENGINE_URL to enable engine analysis." };
  }

  try {
    const res = await fetch(`${engineUrl}/analyze`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ fen, depth, multipv: multiPv }),
      signal: AbortSignal.timeout(ENGINE_TIMEOUT_MS),
    });
    if (!res.ok) return { available: false, error: `Engine returned HTTP ${res.status}` };
    const data = await res.json();
    return {
      available: true,
      evaluation: {
        fen,
        depth,
        score: data.score,        // centipawns or mate
        mate: data.mate || null,
        bestMove: data.bestMove,
        pv: data.pv || [],
        multiPv: data.multiPv || [],
        engine: data.engine || "stockfish",
        engineVersion: data.version || null,
      },
    };
  } catch (e) {
    return { available: false, error: `Engine request failed: ${e.message}` };
  }
}

/**
 * Review a full game (PGN) — delegates move-by-move analysis to the engine.
 * Returns blunder/mistake detection. Bounded to prevent runaway CPU.
 */
async function reviewGame(env, pgn, opts = {}) {
  if (!validatePGN(pgn)) return { available: false, error: "Invalid PGN" };
  const engineUrl = env.CHESS_ENGINE_URL;
  if (!engineUrl) return { available: false, error: "Chess engine not configured." };
  // Game review is expensive; delegate to engine endpoint which handles parsing.
  try {
    const res = await fetch(`${engineUrl}/review`, {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ pgn, depth: opts.depth || DEFAULT_DEPTH }),
      signal: AbortSignal.timeout(30000),
    });
    if (!res.ok) return { available: false, error: `Engine returned HTTP ${res.status}` };
    const data = await res.json();
    return { available: true, review: data };
  } catch (e) {
    return { available: false, error: `Game review failed: ${e.message}` };
  }
}

/**
 * Build a clearly-labeled engine context block for injection into the AI
 * conversation. This is REFERENCE DATA, not instructions. The AI must cite it
 * as engine output and may NOT invent evaluations.
 */
function formatEngineContext(analysis) {
  if (!analysis.available || !analysis.evaluation) return "";
  const e = analysis.evaluation;
  let block = "\n\n--- ENGINE ANALYSIS (Stockfish — factual engine output, not AI opinion) ---\n";
  block += `FEN: ${e.fen}\nDepth: ${e.depth}\n`;
  if (e.mate !== null) block += `Score: Mate in ${e.mate}\n`;
  else if (e.score !== undefined) block += `Score: ${e.score} cp\n`;
  if (e.bestMove) block += `Best move: ${e.bestMove}\n`;
  if (e.pv && e.pv.length) block += `Principal variation: ${e.pv.join(" ")}\n`;
  block += `Engine: ${e.engine}${e.engineVersion ? " " + e.engineVersion : ""}\n`;
  block += "--- END ENGINE ANALYSIS ---\n";
  return block;
}
